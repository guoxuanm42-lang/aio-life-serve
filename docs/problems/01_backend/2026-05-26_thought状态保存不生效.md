# 闪念状态保存不生效（进行中保存后仍为待处理）

## 1. 问题现象
- 前端弹窗把状态选择为“进行中”，点击保存后提示成功，但列表仍显示“待处理”。
- 或切换筛选到“进行中”后找不到刚修改的记录。

## 2. 发生场景
闪念状态字段上线后，前端/接口在某些请求中提交的 `status` 不是后端白名单允许的值，导致更新逻辑忽略该字段。

涉及接口：
- `POST /thought/update`
- `POST /thought/save`
- `POST /thought/query`

## 3. 原因分析
后端对白名单仅允许：
- `pending/ongoing/done/archived`

当客户端提交：
- 中文（如 `进行中`），或
- 大小写不一致（如 `Ongoing`）

会被判定为非法值，从而：
- `save`：落库默认 `pending`
- `update`：status 被置空（等于不更新）
- `query`：condition.status 不生效

## 4. 解决方案
后端统一做状态归一化（normalize）：
- 英文 key：`trim + toLowerCase` 后再校验白名单
- 中文值：映射为英文 key（待处理→pending、进行中→ongoing、已完成→done、已归档→archived）

修复点：
- [ThoughtController.java](file:///d:/my_document/program_product/life_os/aio-life-serve-main/aio-life-serve-main/src/main/java/top/aiolife/record/api/ThoughtController.java)

## 5. 验证方法
- 编辑一条 `pending` 的闪念，状态选“进行中”保存后：
  - 数据库 `thought.status` 应变为 `ongoing`
  - 列表切换筛选到“进行中”应可见
- 若页面仍在“待处理”筛选下，更新为“进行中”的记录会从当前列表消失（符合筛选逻辑）

## 6. 注意事项
- 更新代码后必须重启后端，否则仍会走旧逻辑。
- 推荐前后端统一用英文 key 作为协议值，中文仅做展示层映射。
