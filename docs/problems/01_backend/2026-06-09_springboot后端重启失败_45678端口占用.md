# Spring Boot 后端重启失败：45678 端口被旧进程占用

## 1. 问题现象

执行后端启动命令后，日志最后出现：

```text
[INFO] BUILD FAILURE
[ERROR] Failed to execute goal org.springframework.boot:spring-boot-maven-plugin:3.3.10:run
[ERROR] Process terminated with exit code: -1
```

这不是典型的 Java 编译错误，也不是 Maven 依赖下载失败。日志中还能看到接口请求线程，例如：

```text
http-nio-45678-exec-3
```

这说明后端曾经已经启动成功，并监听过 `45678` 端口，只是后续 Spring Boot 进程被中断、关闭或异常终止。

## 2. 重启时的端口占用

执行端口检查：

```powershell
netstat -ano | findstr :45678
```

返回结果类似：

```text
TCP    0.0.0.0:45678    0.0.0.0:0    LISTENING    29760
TCP    [::]:45678       [::]:0       LISTENING    29760
```

这里说明 `45678` 端口已经被 PID 为 `29760` 的进程占用。通常是旧后端进程没有完全退出，或者本地还有另一个后端实例正在运行，导致新进程无法绑定同一个端口。

排查时只需要关注：

```text
LISTENING    29760
```

类似下面的状态不用处理：

```text
TIME_WAIT    0
```

`TIME_WAIT` 是网络连接关闭后的临时状态，不表示端口仍被某个程序监听占用。

## 3. 解决方案

先确认占用端口的进程：

```powershell
tasklist | findstr 29760
```

确认无误后结束该进程：

```powershell
taskkill /PID 29760 /F
```

然后在后端项目目录重新启动：

```powershell
mvn spring-boot:run
```

完整处理流程：

```powershell
netstat -ano | findstr :45678
tasklist | findstr 29760
taskkill /PID 29760 /F
mvn spring-boot:run
```

## 4. 问题本质

本次问题可以概括为：

**后端运行进程异常结束或残留，导致再次启动时 `45678` 端口被旧进程占用。**

处理思路固定为：

1. 查端口占用；
2. 找到占用端口的 PID；
3. 确认进程身份；
4. 强制结束旧进程；
5. 重新启动后端。

## 5. 固定排查命令

以后只要看到类似：

```text
Port 45678 was already in use
```

或者本地后端启动失败，可以直接按这个顺序处理：

```powershell
netstat -ano | findstr :45678
```

找到 `LISTENING` 后面的 PID，例如：

```text
LISTENING    29760
```

再执行：

```powershell
taskkill /PID 29760 /F
```

最后重启：

```powershell
mvn spring-boot:run
```

这套命令基本可以解决本地 Spring Boot 后端端口被旧进程占用导致的启动失败问题。
