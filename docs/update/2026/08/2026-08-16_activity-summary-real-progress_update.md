# 2026-08-16 活动报告真实生成进度更新

## 更新目标

活动报告生成由同步等待升级为 SSE 真实阶段反馈。界面以业务阶段为主体，百分比仅作为辅助信息，不展示模型隐藏思维链，也不对正文做逐字输出。

## 真实阶段

后端只在实际业务边界发送以下固定事件：

1. `COLLECTING`（15%）：开始汇总九个业务模块。
2. `PREPARING`（40%）：统计完成，开始构建上下文、快照并认领幂等任务。
3. `GENERATING`（55%）：开始调用大模型生成复盘。
4. `SAVING`（90%）：模型返回，开始保存消息和任务状态。
5. `COMPLETED`（100%）：报告保存完成。

前端进度卡主要展示前四个阶段的完成、当前和等待状态，以及当前阶段耗时。底部进度条显示服务端固定百分比，并明确标记为辅助信息，不随时间自动增长。

## 接口

新增：

```text
POST /ai/activity-summary/generate/stream
Content-Type: text/event-stream
```

事件协议：

- `progress`：`{ stage, label, percent }`
- `done`：完整活动总结生成响应
- `error`：`{ code, message, retryable }`

原同步接口 `/ai/activity-summary/generate` 保持兼容。SSE 与同步接口复用同一生成服务，仅通过可选监听器发送阶段变化。

## 执行与断线语义

- 报告生成在独立有界线程池中执行，SSE 超时为 5 分钟。
- 客户端断开只停止事件发送，不中断已开始的模型调用和持久化。
- 前端断线后不自动重新生成，避免和后台任务竞争；用户可刷新会话确认结果。
- 业务失败可按服务端 `retryable` 状态重试，并继续使用原幂等键。
- 页面卸载会关闭浏览器连接，但后台任务仍按既有幂等流程运行。
- 不新增数据库字段或迁移。
