# 失败复盘页增加代办删除操作

## 背景

失败复盘页原先只能填写或修改失败原因。如果某条失败代办已经无须保留，用户需要返回代办清单寻找并删除，操作路径较长。

本次在失败复盘卡片上补充删除入口，让用户可以直接清理整条失败代办。

## 功能使用说明

- 每条失败复盘卡片右侧新增“删除”按钮。
- 点击删除后会显示二次确认，避免误操作。
- 确认后删除整条代办，该记录会从复盘页和其他待办列表中消失。
- 取消确认不会发送删除请求，也不会改变当前列表。
- 删除成功后只移除当前卡片，主题、类型、失败原因和日期筛选保持不变。
- 删除失败时保留原卡片并显示错误提示，用户可以稍后重试。

## 本次调整

### 前端

- 失败复盘卡片将“复盘”和“删除”收拢到统一操作区。
- 删除按钮使用危险操作样式，并通过确认气泡提示删除影响。
- 删除请求进行中只为当前任务显示 loading，同时阻止重复提交。
- 桌面端操作区位于卡片右侧，移动端改为横向排列，避免按钮挤压内容。

### 后端

本次没有新增或修改后端接口，继续复用：

```text
POST /api/tasks/delete
```

请求体只包含任务 ID。后端继续按照任务 ID 和当前登录用户 ID 限定删除范围，并沿用现有 MyBatis-Plus 逻辑删除规则。

## 影响范围

- 不新增数据库字段。
- 不改变失败原因编辑和复盘筛选逻辑。
- 不改变任务明细或现有删除级联规则。
- 不改变代办清单页原有删除行为。

## 验证范围

- 删除前显示二次确认，取消时不删除任务。
- 确认后传递正确任务 ID，成功时只移除对应卡片。
- 删除失败时保留卡片并显示错误提示。
- 删除期间不能重复提交。
- 复盘按钮、筛选条件和空状态保持正常。
- 桌面端与移动端操作区布局正常。
