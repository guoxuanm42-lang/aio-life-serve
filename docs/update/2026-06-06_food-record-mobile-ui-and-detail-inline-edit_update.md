# 美食记录移动端 UI 与详情双击编辑更新（2026-06-06）

## 1. 更新背景

美食模块新增/编辑弹窗在手机端存在信息密度偏高、表单过长、字段一次性铺开的问题；列表卡片在部分桌面宽度下也会因为三列布局和卡片内部内容较多导致视觉拥挤。

同时，美食记录详情页此前只能查看或进入完整编辑弹窗，无法像闪念模块一样在详情态中快速修改具体字段。本次更新围绕“移动端更清爽”和“详情内快速编辑”两个方向进行优化。

## 2. 前端更新

主要修改文件：

- `apps/web-antd/src/views/my-hub/food-record/index.vue`

### 2.1 新增/编辑表单移动端分层

- 桌面端继续保留原有 Modal 编辑体验。
- 手机端将新增/编辑表单调整为接近全屏的录入层。
- 表单按信息层级拆分为：
  - 基础信息
  - 时间信息
  - 材料清单
  - 步骤流程
  - 评价复盘
  - 图片管理
- 手机端默认只展开基础信息，其余分区折叠展示摘要。
- 餐次、状态在手机端改为胶囊按钮组，降低下拉选择成本。
- 手机端底部增加固定操作区，提供取消和保存按钮。

### 2.2 列表卡片信息封层

- 手机端卡片默认突出菜名、状态、日期、分类、餐次。
- 评分、耗时、标签数量等信息压缩成次级摘要。
- 标签展示数量收敛，超出部分使用 `+N` 表示。
- 卡片操作区在手机端保持紧凑，减少垂直空间占用。

### 2.3 卡片网格自适应

- 卡片网格从固定三列调整为自适应布局：

```css
grid-template-columns: repeat(auto-fit, minmax(420px, 1fr));
```

- 该方案按内容区域实际宽度决定两列或三列，避免只按浏览器视口宽度判断导致卡片被左侧菜单和内边距挤压。
- 手机端仍保留单列布局。

### 2.4 详情弹窗双击局部编辑

参考闪念模块详情弹窗的交互方式，在美食记录详情中支持双击字段进入局部编辑。

第一版支持编辑的主记录字段：

- 菜名
- 备菜时间
- 烹饪时间
- 总耗时
- 难度
- 评分
- 成功程度
- 列表总结
- 口味描述
- 问题或不足
- 本次总结
- 下次改进
- 是否值得复做
- 下次尝试建议

材料清单支持双击编辑：

- 材料
- 数量
- 单位
- 备注

步骤流程支持双击编辑：

- 序号
- 标题
- 描述
- 耗时

交互规则：

- 双击可编辑区域进入编辑态。
- 单行字段按 `Enter` 保存。
- 多行字段按 `Ctrl + Enter` 或 `Cmd + Enter` 保存。
- 失焦自动保存。
- `Esc` 取消当前编辑。
- 保存成功后刷新详情数据和卡片列表。
- 保留原有“编辑记录”按钮，用于进入完整编辑表单。

## 3. 数据与接口

- 本次没有新增后端接口。
- 局部编辑复用现有 `updateFoodRecord` 接口。
- 保存详情内单个字段时，会基于当前详情构造完整 `FoodRecordSavePayload`。
- 提交时保留材料清单和步骤流程，避免只编辑单个字段时丢失明细数据。
- 图片管理仍沿用原有编辑模式，详情态第一版不做图片内联编辑。

## 4. 影响范围

- 本次没有修改 Java 后端代码。
- 本次没有新增或修改 SQL。
- 本次没有调整 MCP 工具 Schema。
- 本次主要影响美食记录前端页面的新增/编辑体验、列表卡片布局和详情弹窗交互。
